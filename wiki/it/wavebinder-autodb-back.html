Backend

wavebinder-autodb-back

Backend Node.js che genera endpoint CRUD da configurazione JSON per esporre tabelle database via API.

A cosa serve

  • Esporre tabelle DB senza scrivere route manuali una per una.
  • Gestire lettura/scrittura tramite file di configurazione.
  • Fornire un backend rapido da integrare in progetti WaveBinder.

Repository ufficiale

GitHub: wavebinder/wavebinder-autodb-back

1) Installazione

Mostra esempio 
npm install /path/to/wavebinder-autodb-back-0.0.2.tgz

2) Configura il file JSON

Prima dell'avvio, prepara config.json: definisce porta, connessione DB, tabelle esposte, policy di lettura/scrittura e sicurezza.

Il backend legge il file indicato da CONFIG_PATH (default: ./config.json).

Esempio base

Mostra esempio 
{
  "useApiKey": "NO",
  "apiKey": "nothing",
  "port": 3001,
  "defaultLimit": 100,
  "databases": [
    {
      "name": "main",
      "client": "sqlite3",
      "connection": { "filename": "./restaurant.sqlite" },
      "useNullAsDefault": true,
      "schemas": [
        {
          "name": "main",
          "tables": [
            {
              "name": "restaurants",
              "primaryKey": "id",
              "readOnly": false
            }
          ]
        }
      ]
    }
  ]
}

Policy campi

  • readOnly: se false permette scrittura/lettura altrimenti blocca la scrittura (default a false).

Esempio senza scrittura

Mostra esempio 
{
  "name": "restaurants",
  "primaryKey": "id",
  "readOnly": true
}

3) Avvio backend

Mostra esempio 
# PowerShell
$env:CONFIG_PATH = ".\\config.json"
npx wavebinder-autodb-back
In alternativa, se stai eseguendo il progetto backend direttamente: npm start

4) Endpoint generati

Ogni voce in schemas[].tables[] genera CRUD sotto /api/{schema}/{table}.

Gli endpoint esposti dipendono da readOnly nella tabella: con readOnly: true sono permesse solo operazioni di lettura, quindi risultano visibili solo endpoint GET; con readOnly: false sono disponibili anche gli endpoint di scrittura.
  • GET /api/main/restaurants (filtri/sort/paginazione)
  • GET /api/main/restaurants/:id
  • POST /api/main/restaurants
  • PUT /api/main/restaurants/:id
  • DELETE /api/main/restaurants/:id

5) Uso nel progetto WaveBinder

Configura il servizio esterno (esempio extapi.json):

Mostra esempio 
{
  "target": "http://localhost:3001/api",
  "secure": false,
  "authorization": null
}

Mapping serviceName (importante)

Il valore serviceName nei nodi deve combaciare con la chiave registrata nella mappa servizi passata a new WaveBinder(...).

Mostra esempio 
const extApis = new Map();
extApis.set("api", EXT_API_CONFIG);

const wb = new WaveBinder(
  LICENSE,
  PROTO_NODES,
  extApis,
  customFunctions
);
  • Con extApis.set("api", ...), i nodi devono usare serviceName: "api".
  • Con target: "http://localhost:3001/api" e la.addr: "/main/restaurants", la chiamata finale diventa http://localhost:3001/api/main/restaurants.

Autenticazione

  • Se useApiKey = "YES", il backend richiede header x-api-key.
  • Se useApiKey = "NO", endpoint pubblici.
